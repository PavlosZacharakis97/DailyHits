# Формат CSV для импорта песен

Команда:

```sh
docker compose exec backend python manage.py import_songs /app/data/songs.csv --dry-run   # проверка, ничего не сохраняет
docker compose exec backend python manage.py import_songs /app/data/songs.csv             # импорт
```

Файл должен лежать внутри папки `backend/` (контейнер видит её как `/app`), например `backend/data/songs.csv`.
Папка `backend/data/` не попадает в git.

Пример: [import-example.csv](import-example.csv) — одна правильная строка и одна с ошибками. Запустите его с `--dry-run`, чтобы увидеть отчёт.

## Как сохранить файл

- Excel: «Файл → Сохранить как → CSV UTF-8».
- Google Таблицы: «Файл → Скачать → CSV».
- Разделитель колонок — запятая, точка с запятой или табуляция: определяется сам.
- **Списки внутри ячейки разделяются `|`** (вертикальная черта): `Hard Rock|Glam Rock`.

## Колонки

Первая строка — названия колонок, как в таблице ниже. Порядок колонок не важен, лишние колонки игнорируются.

| Колонка | Обязательно | Значение |
|---|---|---|
| `title` | да | официальное название, без «(Remastered)» и «– Radio Edit» |
| `artist` | да | основной исполнитель, как на оригинальном релизе |
| `artist_country` | для нового исполнителя | ISO-код страны: `GB`, `US`, `SE`… |
| `artist_type` | нет | `solo` (по умолчанию), `group`, `duo`, `collaboration` |
| `artist_members` | нет | участники через `|`: `Freddie Mercury|Brian May` — нужны для жёлтой плитки «исполнитель» |
| `featured` | нет | приглашённые через `|`; новому исполнителю добавьте страну: `Daddy Yankee:PR` |
| `year` | для проверки | год первого официального релиза |
| `genre` | для проверки | один жанр из справочника: `Rock`, `Pop`, `R&B/Soul`… |
| `styles` | для проверки | 1–2 стиля через `|` |
| `vocal` | для проверки | `male`, `female`, `mixed`, `instrumental` |
| `language` | для проверки | ISO-код (`en`, `es`, `ko`) или название (`English`); без слов — `zxx` |
| `themes` | для проверки | 1–2 темы через `|`, **первая — главная** |
| `difficulty` | нет | `easy`, `medium` (по умолчанию), `hard` |
| `youtube_id` | нет | 11 символов из ссылки `youtube.com/watch?v=…` |
| `musicbrainz_id` | нет | ID из MusicBrainz; по нему повторный импорт находит песню |
| `aliases` | нет | варианты написания через `|`: `Despasito|Деспасито` |
| `sources` | нет | ссылки на источники через `|` |
| `editions` | нет | коды версий игры через `|`; по умолчанию `world` |
| `notes` | нет | заметки модератора |
| `fact1` … `fact5` | минимум 3 для проверки | текст факта своими словами |
| `fact1_strength` … | с фактом | `easy` (почти не выдаёт ответ), `medium`, `strong` (почти выдаёт) |
| `fact1_source` … | с фактом | ссылка на источник факта |

«Для проверки» — строку можно импортировать и без этого поля (получится черновик), но перевести песню в «Подтверждена» не получится, пока поле не заполнено.

Названия жанров, стилей, тем и стран — точно как в [справочнике](../backend/apps/catalog/seed/reference.yaml), регистр не важен.

## Что делает импорт

| Ситуация | Результат в отчёте |
|---|---|
| Песни ещё нет | `created` — создаётся черновик |
| Песня есть, черновик, данные отличаются | `updated` |
| Песня есть, всё совпадает | `unchanged` |
| Песня есть, она «На проверке» или «Подтверждена» | `conflict` — **не перезаписывается**, в отчёте видно, чем CSV отличается от базы |
| Ошибка в строке | `error` — строка пропущена, остальные импортируются |

- Песня ищется по `musicbrainz_id`, а без него — по названию (без учёта регистра) и основному исполнителю.
- **Пустая ячейка — «не трогать»**: если факты дописаны в админке, а в CSV колонки фактов пустые, факты останутся.
- Неизвестные жанр, стиль, тема, страна, язык или версия игры **не создаются** — строка получает ошибку. Добавьте значение в справочник или исправьте опечатку.
- Новые исполнители и участники групп создаются сами.
- Каждый запуск с отчётом по строкам сохраняется в админке: «Импорт → Импорты».

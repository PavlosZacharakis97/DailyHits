## 1. Продукт

DailyHit (домен daylihit.live) — ежедневная игра в стиле Wordle/Spotle.

- Каждый день одна загаданная песня из числа самых известных в мире.
- У игрока 10 попыток. Он вводит название, выбирает песню из выпадающего списка (autocomplete).
- После каждой попытки сервер сравнивает выбранную песню с загаданной по 8 признакам (плиткам) и возвращает цвет каждой плитки: 🟩 green / 🟨 yellow / ⬜ gray, а для года — стрелку направления.
- После 5-й попытки открывается подсказка-факт №1, после 8-й — факт №2.
- После окончания игры (угадал / 10 попыток / сдался) показывается ответ и ссылка на YouTube.
- Аудио нет и не будет. Песни не скачиваются и не хранятся. Только текстовые данные о песнях.

Старт: одна версия игры (edition world) — мировые хиты, 365+ проверенных песен. Архитектура должна позволять позже добавить другие версии (ru и т.д.) без переделки схемы.

## 5. Docker

Сервисы:

- `db` — официальный образ postgres:17, данные в именованном volume db_data, healthcheck (pg_isready).
- `backend` — собирается из backend/Dockerfile, стартует только после healthy db (depends_on: condition: service_healthy).
- `frontend` — пока не создавать, но предусмотреть в README, как он будет подключён.

Требования:

- Контейнеры общаются по именам сервисов (`DATABASE_URL=postgres://...@db:5432/...`), не через localhost.
- Dev: bind-mount кода, автоперезагрузка Django, порт 8000.
- Prod: Gunicorn, DEBUG=False, код в образе, collectstatic, процесс не от root, порт БД наружу не публикуется.
- Секреты только в .env. .env в .gitignore, в репозитории только .env.example.
- `docker compose down` не должен удалять данные. В README явно предупредить, что `down -v` удаляет базу.

## 6. Модель данных

Все значения-категории — справочники (отдельные таблицы), а не свободный текст. Это исключает расхождения вида «Rock» / «рок» / «Рок ».

### Справочники

- **Region** — регион мира: Европа, Северная Америка, Латинская Америка, Азия, Африка, Океания, Ближний Восток.
- **Country** — name, iso_code (уникальный), region → Region.
- **Language** — name, iso_code (уникальный).
- **Genre** — крупное семейство (~12–15): Поп, Рок, Метал, Хип-хоп, R&B/Соул, Электроника, Диско/Фанк, Кантри, Фолк, Латино, Регги, Джаз/Блюз, Классика/Саундтрек. Поле related — M2M на себя, симметричное (Рок ↔ Метал, R&B/Соул ↔ Хип-хоп, Диско/Фанк ↔ R&B/Соул и т.п.). Используется для жёлтого цвета.
- **Style** — поджанр (~40–60): Хард-рок, Глэм-рок, Гранж, Синти-поп, Диско, Трэп, Хаус и т.д. Поле genre → Genre (обязательно). Подготовь полный список стилей с привязкой к жанрам как seed-фикстуру — я его проверю.
- **ThemeGroup** и **Theme** — тема песни (по смыслу текста). Фиксированный список:
  - Любовь: Влюблённость, Расставание / разбитое сердце, Страсть, Ревность / измена
  - Веселье: Вечеринка / танцы, Свобода / беззаботность, Лето / отдых
  - Жизнь и чувства: Ностальгия / воспоминания, Одиночество / грусть, Мотивация / сила, Взросление / самопознание
  - Общество: Протест / политика, Война / мир, Социальные проблемы, Деньги / успех
  - Истории: Рассказ / персонаж, Город / место, Дорога / путешествие
  - Особые: Религия / духовность, Смерть / утрата, Фантазия / сюрреализм
- **Edition** — версия игры: code (уникальный: world, позже ru…), name, timezone, is_active.

Все справочники загружаются management-командой `seed_reference` (идемпотентно, можно запускать повторно).

### Исполнители

- **Person** — человек (солист, участник группы): name, musicbrainz_id (unique, nullable).
- **Artist** — name, type (solo / group / duo / collaboration), country → Country, musicbrainz_id (unique, nullable).
- **ArtistMember** — artist → Artist, person → Person. Уникальная пара. Связывает, например, Freddie Mercury с Queen и с его сольным проектом.

### Песня

**Song**:

- title — официальное название, без «(Remastered…)», «– Radio Edit».
- year — год первого официального релиза (CHECK: 1900 ≤ year ≤ текущий год).
- genre → Genre — ровно один.
- styles — M2M Style, 1–2.
- themes — через промежуточную модель с полем is_primary; 1–2 темы, ровно одна главная.
- vocal — choices: male / female / mixed.
- language → Language.
- youtube_video_id — nullable. Если пусто, API отдаёт ссылку на поиск YouTube «{artist} {title}».
- musicbrainz_id — unique, nullable.
- difficulty — easy / medium / hard (для балансировки расписания).
- status — draft / review / verified. В игре (поиск, расписание) участвуют только verified.
- editions — M2M Edition.
- sources — список URL-источников (JSONField или отдельная таблица).
- notes — внутренние заметки модератора для спорных случаев.
- created_at, updated_at.

**SongArtist** — song, artist, role (primary / featured). Ровно один primary на песню. Уникальная пара song+artist.

**SongAlias** — альтернативные написания для поиска («Деспасито», «Always Love You»).

**Fact** — song, text, strength (easy / medium / strong), order, source_url (обязательно), is_verified. Правила: минимум 3 факта на verified-песню; факт своими словами; никаких цитат из текста песни; факт уровня easy не должен содержать название песни или имя исполнителя (проверять автоматически в валидации).

Уникальность песни: title (case-insensitive) + primary artist. Плюс unique musicbrainz_id.

Страна песни для плитки = страна primary-исполнителя. Отдельно на песне не хранить.

### Расписание

**DailyPuzzle** — edition, date, song, number (порядковый номер выпуска). Уникальная пара (edition, date). Валидация (в clean() и в команде check_schedule):

- песня в статусе verified и входит в эту edition;
- песня не повторяется в той же edition чаще, чем раз в 365 дней;
- один и тот же primary-исполнитель не два дня подряд;
- предупреждение, если 3 дня подряд один жанр или одинаковая сложность hard.

### Игровая сессия (защита от подглядывания)

Сервер, а не клиент, хранит прогресс — иначе подсказки и ответ можно получить, подменив счётчик.

- **GameSession** — id (UUID), player_token (анонимный UUID из httpOnly cookie), puzzle → DailyPuzzle, status (in_progress / won / lost / gave_up), created_at, finished_at. Уникальная пара (player_token, puzzle).
- **Guess** — session, song, attempt_number, created_at. Уникальные пары (session, attempt_number) и (session, song) — одну песню дважды угадывать нельзя.

## 7. Логика сравнения (самое важное)

Отдельный модуль `apps/game/comparison.py`, чистые функции без обращения к БД внутри (данные передаются готовыми DTO). Покрытие тестами — 100%, на каждое правило — тест на green, yellow, gray и граничные случаи.

| Плитка | Green | Yellow | Gray |
|---|---|---|---|
| Исполнитель | тот же primary-исполнитель | есть общий Person среди участников исполнителей (Freddie Mercury ↔ Queen) или primary одной песни есть среди featured другой | иначе |
| Год | совпадает | разница ≤ 5 лет | иначе |
| Жанр | тот же Genre | Genre в related | иначе |
| Стиль | пересечение множеств стилей не пусто | есть стиль из того же Genre, что и любой стиль ответа | иначе |
| Вокал | совпадает | — | иначе |
| Тема | пересечение тем не пусто | есть тема из той же ThemeGroup | иначе |
| Страна | та же Country | тот же Region | иначе |
| Язык | совпадает | — | иначе |

Для года при не-green дополнительно возвращать direction: up (ответ позже) / down (ответ раньше).

Пороги (5 лет, 10 попыток, попытки для подсказок 5 и 8) — в настройках, не хардкодом.

## 8. REST API

Префикс `/api/v1/`. Все ответы JSON. Ответ дня никогда не попадает в ответ API до завершения игры. Это требование покрыть тестами (проверить, что ни один ответ in-progress сессии не содержит id/title загаданной песни).

- `GET /puzzles/today?edition=world` — date, number, max_attempts, текущее состояние сессии игрока (попытки, плитки, статус). Создаёт сессию при первом обращении.
- `GET /songs/search?q=...&edition=world` — autocomplete. Минимум 2 символа, максимум 10 результатов, только verified-песни. Поиск по title, алиасам и исполнителю; без учёта регистра и диакритики (unaccent), с нечётким совпадением (pg_trgm). Отдаёт только id, title, artist.
- `POST /puzzles/today/guess` — `{ "song_id": ... }`. Возвращает 8 плиток (key, value для отображения, color, direction?), номер попытки, статус игры. Ошибки: игра окончена, песня уже была, лимит попыток, несуществующая песня.
- `GET /puzzles/today/hints` — только разблокированные факты (после 5-й и 8-й попытки; порядок: easy → strong).
- `POST /puzzles/today/give-up` — завершить игру.
- `GET /puzzles/today/reveal` — ответ (title, artist, year, все факты, YouTube-ссылка). Только для завершённой сессии, иначе 403.
- `GET /puzzles/{date}` и те же действия для архива — заложить в архитектуру, архивные даты не дальше 50 дней назад; будущие даты — всегда 404.

Требования: throttling (DRF) на search и guess; единый формат ошибок; OpenAPI-схема (drf-spectacular) — фронтенд будет строиться по ней.

Смена дня — по таймзоне edition (настраиваемо, по умолчанию UTC). Вся логика «какой сегодня день» — в одной функции.

## 10. Импорт и качество данных

Конвейер: внешние источники → staging → автопроверка → ручная проверка в админке → verified.

Источники: Wikidata, MusicBrainz (год, страна, состав, MBID), Last.fm (теги → маппинг на наши Genre/Style), Wikipedia (основа для фактов, переписывать своими словами).

- `import_songs <csv>` — загрузка в staging / draft. Идемпотентно: повторный запуск обновляет записи по musicbrainz_id, а не создаёт дубли. Неизвестные жанры/стили/страны не создаются автоматически — попадают в отчёт.
- `validate_data` — отчёт: пустые обязательные поля, подозрительные годы, вероятные дубли (trigram similarity по title+artist), меньше 3 фактов, факты без источника, easy-факт содержит название/исполнителя, больше 2 тем/стилей.
- `check_schedule --days 60` — валидация расписания и пропусков.
- `seed_reference` — справочники.
- `scripts/backup.sh` — pg_dump из контейнера, сжатие, ротация (хранить 14 последних).

Правила заполнения (зафиксировать в docs/data-rules.md):

- Год — первый официальный релиз песни, не ремастер, не сборник.
- Исполнитель — указанный на оригинальном релизе. Каверы не используем.
- Жанр и стиль — только из фиксированного списка.
- Страна — страна primary-исполнителя.
- Название — официальное, без пометок ремастера/редакций.
- Темы — по смыслу текста, а не по настроению музыки; максимум 2, одна главная.
- Факты — своими словами, с источником, без цитат из текста песни.
